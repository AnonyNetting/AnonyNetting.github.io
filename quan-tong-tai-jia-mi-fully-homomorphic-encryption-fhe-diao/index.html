    Preliminary

    同态加密指 将原文加密而得到的密文可以被用来进行与原文相同的计算，形式化的表示为：

    假定我们有plaintext : pt0, pt1, ... ptn-1,对这些plaintext我们有计算需求假定为f(pt0, pt1, ... ptn-1) = ptresult；此外，对于这些plaintext我们有加密方案Enc(pti) => cti, i ∈ [0, n) ∩ Z，产生的ciphertext ct0, ct1, ... ctn-1执行上面同样的计算需求f(ct0, ct1, ... ctn-1) = ctresult。如果对这个密文上的计算结果执行解密Dec(ctresult)，我们就会得到Dec(ctresult) = ptresult。

    这说明借助同态加密，直接在密文上操作和在明文上操作然后加密，效果是一样一样的！一个典型的应用场景是：数据持有者想对其持有的大量数据进行计算，奈何其拥有的计算资源不足，想借助云服务器的算力完成该计算。如果按照现在流行的做法，那当然是将数据传输到云服务器，然后运行事先写好的程序进行计算。但如此一来，敏感数据便在云服务器上暴露无遗。同态加密正好解决了此问题，数据持有者传输数据前先将数据加密，云服务器在接收到数据后照例计算，只不过这次是在密文上进行的，云服务器啥都看不到。待得到结果后再将结果的密文返还给数据持有者，数据持有者解开后即得最终结果。[1]

    一般来说，这里要执行的计算需求f不会太复杂，或者说，更复杂的需求最终都可以拆解成加法和乘法，所以我们认为 可以在加密结果上执行加法和乘法的话我们就认为它是一种同态加密。这里举一个简单的具体做法样例，在那之前简单介绍LWE(Learning With Error)问题[2]：

    对于形如以下的线性同余方程组(将所有约等于号看作等号)，根据中国剩余定理(Chinese Remainder Theorem, CRT)我们可以非常容易地解出方程组的解（下文还会用到这个解法，这里只要知道易解就可以）。

    但是，这个问题的难度可以被轻松提高到对量子算法也难解的程度：如果我们为每个式子的左端都添加一个误差(error)，这个误差不需要很大，比如在这里error = ±1即可。那么此时这个线性同余方程组就没有多项式时间复杂度下的解法（除了逐一代入数值验算以外没有更快的方法，原因自行学习，在此不证），在密码学观点下我们就可以认为其不可破解。

    在这样一个基础上看CKKS同态加密的简化分析：如果我们有plaintext m，对之执行特定的编码算法得到多项式encode(m)，更进一步对其通过形如 - a * s + e + encode(m) mod Q的计算加密得到密文(- a * s + e + encode(m) , a) mod Q；其中我们需要保证a的随机性，s是用于加密encode(m)的密钥，e是极小（相对于encode(m)来说）的偏差，用于进一步掩盖encode(m)；a, s, e也是多项式，Q是模数，所有多项式系数都应当对Q取模，落在[0, Q) ∩ Z的范围内。

    首先看这种做法带来的加密特性。在保留s不公开（即s是私钥）的条件下，密文第一项构成了如上图中右侧的计算结果，第二项给出了上图中左侧的系数，进而我们知道这种情况下无法解s，进而无法解出e+encode(m)。

    在使用私钥s的条件下，我们则可以通过- a * s + e + encode(m) + a * s 计算出 e + encode(m)。这样虽然还没有严格恢复最初的encode(m)，但是由于e极小，且持有私钥的一方具有e是如何分布的先验知识（因为e最初就是私钥持有者添加的），我们认为私钥持有者具备从e + encode(m)中提取出encode(m)的能力，或者干脆认为这是近似计算：恢复的数据并不严格等于plaintext计算得到的数据，但在可接受的精度范围内。

    接下来我们来验证这种做法如何实现加法和乘法上的同态。假定我们有plaintext m0和m1，共用私钥s并分别产生了ciphertext ct0 (- a0 * s + e0 + encode(m0) , a0) 和 ct1 (- a1 * s + e1 + encode(m1) , a1)。当对它们执行加法时：

    ct0 + ct1 = (- a0 * s + e0 + encode(m0) , a0) + (- a1 * s + e1 + encode(m1) , a1)
    = (- (a0 + a1) * s + e0 + e1 + encode(m0) + encode(m1), a0 + a1);

    很明显我们使用同样的解密算法时，我们能够得到e0 + e1 + encode(m0) + encode(m1)。结果中的噪音线性增大了，这个问题放在稍后讨论。总体来说，我们仍然实现了同态加法。当对它们执行乘法(假定采用coefficient-wise multiplication)时：

    ct0 * ct1 = (- a0 * s + e0 + encode(m0) , a0) * (- a1 * s + e1 + encode(m1) , a1)
    = ((a0 * a1) * s2 +
    ((-(e0 + encode(m0)) * a1) + (-(e1 + encode(m1)) * a0)) * s
    + (e0 + encode(m0)) * (e1 + encode(m1)), a0 * a1);#1

    看起来引入了许多问题：

    其一，还能通过上面的解密方式解出plaintext吗？很明显是不可以的。在最初的解密中，我们有
    ct = ( -a * s + m + e, a); sk = (1, s);
    => pt = <ct, sk>(向量的点积) = -a * s + m + e + a * s = m + e;
    而现在我们找不到这样的点积关系，除非我们将密文ct和密钥st做扩展，例如将ct和sk扩展成
    ct = ((a0 * a1) * s2 +
    ((-(e0 + encode(m0)) * a1) + (-(e1 + encode(m1)) * a0)) * s
    + (e0 + encode(m0)) * (e1 + encode(m1)), ((e0 + encode(m0)) * a1) + ((e1 + encode(m1)) * a0), -a0 * a1);
    sk = (1, s, s2);
    这种做法很明显不可接受：ct和sk的大小如果每次运算就扩展一次，一个越算越大（数据量意义上）的算法很难说是同态加密；另外，服务器侧由于缺少s是何值的信息（因为其实ct在服务器侧看起来只是形如(b,a)的两个多项式），其实是不能像上面的式子一样拆分出来关于s的系数多项式的。因而在计算密文上的乘法时不能采取上面那么直观的乘法，需要采用改进方案。
    让我们重新分析一下密文上的乘法运算。假定我们有ct0 = (- a0 * s + e0 + encode(m0) , a0) = (b0, a0) 和 ct1 = (- a1 * s + e1 + encode(m1) , a1) = (b1, a1)；根据同态的特性，计算ct0 * ct1出的结果ct2 = (b2, a2)应当满足：
    <ct2, sk> = <ct0, sk> * <ct1, sk> = b2 + a2 * s = (b1b0) + (a1b0 + a0b1) * s + (a1a0) * s2；
    如果b2 = (b1b0), a2 = (a1b0 + a0b1)，那么就丢失了(a1a0) * s2。为了达成这个补偿，算法引入了辅助密钥evk(Evaluation Key，其实在Figure 1中有提到)的概念：既然b2 = (b1b0), a2 = (a1b0 + a0b1)没有完整体现出密文上的乘法，那么有没有可能提供一个偏移bias = (bbias, abias)，或者说补偿来同时改变b2 = (b1b0)和a2 = (a1b0 + a0b1)，即ct2’ = ct2 + bias = (b1b0, a1b0 + a0b1) + (bbias, abias), 使得<ct2', sk> = (b1b0) + (a1b0 + a0b1) * s + (a1a0) * s2呢？似乎看起来很简单，只要(bbias, abias) = (0, a1a0s)不就好了？但是，evk应当具有通用性，毕竟我们不可能预知到会有哪些密文会在一起计算乘法。那a1a0根据两个乘数的密文来现场计算，(bbias, abias) = (0, s)呢？不要忘记s就是我们的sk的唯一信息，它是不可以被发布出去的。
    为了解决这个问题，CKKS方案提出了这样的evk设计方案：evk = (b', a') = (-a' * s + e' + P * s2, a') mod P·Q， 其中a', e'分布函数和用于生成公钥时a, e的分布函数保持一致，唯一区别在于在evk中所有多项式系数的模数被更改成P×Q，P是被引入的新的大数，并且保证P与Q互质。
    基于这个evk得到的bias = P-1(a1a0)evk = (P-1(a1a0)(-a') * s + P-1(a1a0)e' + (a1a0) * s2, P-1(a1a0)(a'))；
    验算这个bias的解密结果<bias, sk>
    = P-1(a1a0)(-a') * s + P-1(a1a0)e' + (a1a0) * s2 + P-1(a1a0)(a')*s
    = P-1(a1a0)e' + (a1a0) * s2
    ≈ (a1a0) * s2。
    所以在CKKS方案中ct0 = (b0, a0), ct1= (b1, a1)运行乘法的结果ct2应当是
    ct2
    = (b1b0, a1b0 + a0b1) + P-1a1a0*evk
    = (b1b0 + P-1(a1a0)(-a') * s + P-1(a1a0)e' + (a1a0) * s2, a1b0 + a0b1 + P-1(a1a0)(a'))
    = (b1b0 + P-1(a1a0)b', a1b0 + a0b1 + P-1(a1a0)a')；

    在通过引入evk来解决了基本的同态乘法实现后，我们来观察这个结果被解密后的实际输出

    <ct2, sk>
    = b1b0 + P-1(a1a0)b' + a1b0s + a0b1s + P-1(a1a0)a's
    = (a0a1) * s2 + P-1(a1a0)e'
    + (([ ( - a0 ) * s + e0 + encode(m0)] * a1) + ([ ( - a1 ) * s + e1 + encode(m1)] * a0)) * s
    + ( ( - a0 ) * s + e0 + encode(m0)) * ( ( - a1 ) * s + e1 + encode(m1))
    = (a0a1) * s2 + P-1(a1a0)e'
    +     (-2) * (a0a1) * s2 + (a1 * (e0 + encode(m0)) + a0 * (e1 + encode(m1)) ) * s
    +     (a0a1) * s2 + (e0 + encode(m0)) * (e1 + encode(m1)) - ( a1 * (e0 + encode(m0)) + a0 * (e1 + encode(m1)) ) * s
    = 理想输出部分 + 噪音部分
    = encode(m0) * encode(m1)
    + e0e1 + e0 * encode(m1) + e1 * encode(m0) + P-1(a1a0)e'

    其中P-1(a1a0)e'由于认为P是较大的数，我们可以认为其不影响输出。但是，考虑乘法下的其余噪声项，以及加法下的噪声项，我们发现相比较于同态下的加法，乘法下每次计算造成噪声增大的幅度远大于加法。我们说即使密文下的计算结果复原后存在噪声我们也可以接受，是因为噪声相较于理想输出太小，可以通过噪声分布的先验知识消除掉，或者即使复原结果包含噪声，其精度也在可接受的范围内。那么通过上面的分析我们发现，无论是计算加法还是乘法，密文中的噪声都在逐渐扩大（尤其乘法会大幅扩大噪声）；可以预见到，当密文上的计算执行了足够多次数后，噪声会超过可接受的范围，从而使得解密结果不可接受。这就引出了第二个问题，服务器端计算过程中如何限制噪声增长，或者消除已经产生的噪声？CKKS提出的方案叫做“重缩放”。

    到这一步就不得不介绍实际的CKKS算法[3]：

    CKKS-Original version

    初始化
    设定参数 λ 作为安全等级参数， L作为模数的深度上限（“深度上限”是什么意思在本节下文介绍），等于2的整数次幂的基底p。
    选择一个2的幂N，用于指定接下来的运算所处在的多项式环R/(xN+1)。
    选择一个特殊模数P用于产生evk。另外根据基 p>0，定义Q=q0⋅pL-1；以上数字的选取应当使得N和P⋅Q满足安全等级 λ。另外注意，在非RNS的CKKS中，对应所有层上的pi可以都是相等的，都等于p。知乎上有一篇文章说在非RNS的CKKS中pi彼此不相等，只是靠近p，这种做法在RNS和非RNS的CKKS中都有采用，但在这篇文章中采用的是所有p相等。[5]的Section2提到pi彼此不等，只是靠近p的特性被描述为RNS-CKKS的创新，与原版作为区分。另一方面，Microsoft SEAL库的非RNS CKKS example中，所有p都是靠近但彼此不同的素数，证明非RNS CKKS也可以使用p彼此不等的方法。
    注意到任何密文的缩放因子都不能过于接近coeff_modulus的总大小（即Qi, 0≤i＜L），否则密文将无法存储放大后的明文。当Qi, 0≤i＜L降低到只剩一个素数，即Q0时，该素数必须比S大几位，以保留明文的小数点前值，所以q0的数量级是要稍大于p的。
    CKKS本身是一个有限层次全同态加密（Fully Leveled Homomorphic Encryption），每一个密文对应了一个深度，深度一共有L个层次，最高深度L即为深度上限。最大的层次中模数为Q=QL-1=q0⋅pL-1，接着是QL-2=q0⋅pL-2,..., Q1=q0⋅p， Q0=q0。一个plaintext在刚被加密时会落在第L层，而随着每次密文下执行乘法，其对应密文应当被降低1层（这也意味着CKKS密文下的乘法最多可能执行L次，因此并不是全同态加密算法）。随着层次的减少，模数（也就是本层的密文大小上限）在不断减小。这个设定的目标是为了解决乘法中密文增大，以及噪音增大的问题（对上面的简化方案的分析我们已经认识到了噪音增大的问题，密文增大的原因将在下文“编码”和“解码”后介绍），此时必须通过重缩放操作，调整密文到浅一层，同时规模减小。细节将在重缩放的部分叙述。
    此外还要选择一个私钥相关的分布χs用于产生s，一个错误分布χe用于产生e，以及一个随机分布χr在“加密”步骤中使用。

    编码
    编码的功能是将要加密的原文转写成为多项式，以使用CKKS算法后续的计算操作。从结论上来说，对原z编码的过程可以表示为m(X)=⌊σ−1(Δ⋅π−1(z))⌉∈Z[X]/(XN+1)。其中包含了两种映射的逆映射：
    1. 自然投影映射π:∀t∈H,π(t)=(t0,t1...tN/2)∈CN/2；H是CN的子环，H={z∈CN:zj与zN−j互为共轭}。
    2. 规范嵌入映射σ:∀m∈C[X]/(XN+1)，σ(m)=m(ξ),m(ξ3),...,m(ξ2N−1))∈CN，这里ξ2i−1代表了多项式XN+1的N个本原根。
    CN/2是复数向量空间，也是CKKS的明文空间。Δ是一个大数，被称作缩放因子（scaling factor），用于放大整数部分（在所有pi相等的情况下，等于“初始化”中的基 p；否则，至少应当与p保持相同数量级）。
    这里涉及了很多数论知识。简单来说，π−1用于将定义在CN/2上的z扩展，乘以缩放因子Δ放大所需要的精度部分使其全部变为整数，σ−1使其最终转换成实多项式R[X]/(XN+1)。为了使其变为整数多项式，再对结果取整⌊⌉（称作coordinate-wise randomized rounding）。两个映射具体如何操作在下文介绍CKKS自举的部分详细解释。

    解码
    解码运算的步骤与编码完全相反：
    1. 用缩放因子的倒数Δ−1乘m(X)
    2. 计算σ(Δ−1⋅m)∈H
    3. 计算π(σ(Δ−1⋅m))∈CN/2
    注意这里先乘上了Δ−1还原为实数类型，目的是减少数字大小，进而减轻后面运算的规模。可以看出一份明文经过一次编码和解码之后，不一定和原来相等，这是由浮点运算，以及编码时的舍入造成的。但是只要误差足够小，不会很影响计算。

    可见，如果将σ和π一同视作一个函数f，编码步骤抽象成m(X)=Δ⋅f−1(z)；对这个编码结果执行加密后的密文也包含了一个缩放因子Δ。那么进而，两个密文相乘的结果中缩放因子Δ就会变成Δ2，也就是上文中提到的“密文增大”。

    密钥生成
    密钥生成步骤包含了三组密钥的生成过程：私钥sk用于解密，公钥pk用于加密，辅助密钥evk用于完成上文分析所提到的同态乘法。
    实例化χs → s, χe → e, U([0, Q)) → a = RQ[X]/(XN+1)；私钥sk = (1, s); 公钥pk = (b, a) = ( -a · s + e, a) mod Q。
    实例化χe → e', U([0, P·Q)) → a' = RPQ[X]/(XN+1)；辅助密钥evk = (b', a') = ( -a' · s + e' + P · s2, a') mod P·Q。

    加密
    实例化χr → r, χe → e0, χe → e1, 对于经过编码的明文多项式m, 密文c = r · pk + (m + e0, e1) = (r · b + m + e0, r · a + e1) mod Q。
    因为c ∈ RQ2模数是Q，根据“初始化”部分的定义，可见刚加密得到的密文落在深度L上。

    解密
    对于处在模数Ql对应层上的sk，验算<c, sk>
    = r · b + m + e0 + r · a + e1
    = r · (-a · s + e) + m + e0 + r · a · s + e1 · s
    = m + e0 + e · r + e1 · s mod Ql
    虽然看起来噪声项非常多，但是相较于Ql足够小（即使多次计算造成噪声增大，通过下文介绍的重缩放也能控制其大小），所以没有问题。

    加法
    对于c0 = (b0, a0) ∈ RQl2, c1 = (b1, a1) ∈ RQl2，加法结果c2 = (b2, a2) = (b0 + b1, a0 + a1) ∈ RQl2。

    乘法
    对于c0 = (b0, a0) ∈ RQl2, c1 = (b1, a1) ∈ RQl2, evk = (b', a') ∈ RQl2, 特殊模数P，乘法结果c2 = (b2, a2) = (b1b0 + P-1(a1a0)b', a1b0 + a0b1 + P-1(a1a0)a') ∈ RQl2。

    重缩放
    正如上文所言，重缩放是为了解决同态乘法带来的噪声增大和密文增大两个问题。具体做法而言，重缩放执行了以下操作：
    给出密文c∈RQl2，以及一个新模数Ql’<Ql，对c中所有系数作如下处理：crs←⌊(Ql’/Ql)⋅c⌉ mod Ql’, 输出crs∈RQl’2。简单来说，上一次两个乘数密文处在Ql对应的层上，乘法运算的结果密文也处在Ql对应的层上。为了解决噪音和密文增大的问题，结果密文上的所有系数都应当作上述处理（(Ql’/Ql)在降1层的情况下其实就是p-1），使重缩放后的密文落在Ql’对应的l-1层上，Ql’ = q0⋅pl-1。下图给出了重缩放能够限制噪声增长的直观解释。

    CKKS-RNS version

    以上具体操作已经完全能够执行CKKS全部功能。但是，出于安全和充足的可执行乘法次数考虑，基p，特殊模数P和深度L都会设置比较大；模非常大的模乘会非常消耗计算资源，也非常慢。为了解决这个问题，CKKS的RNS变体中Q和P被设置成为可以分解成若干较小互质数分解的形式，我们可以使用中国剩余定理[4]将模Q和模PQ的计算转换成为若干个并行且定义在较小模pj, qi上的多项式计算。

    例如，我们假定现在有一组定义在R35[X]/(X2+1)的两个多项式(10 + 12x)和(8 + 20x)，对之执行乘法。首先确认一下直接在R35上计算得出的结果：(10 + 12x)(8 + 20x) = 80 + 296x + 240x2 = 80 + 296x - 240 = 15 + 16x。考虑35 = 5 × 7，我们将这两个多项式各自在R5和R7上求出分解：
    对于在R35[X]/(X2+1)上的(10 + 12x)，在R5[X]/(X2+1)上分解得到(10 + 12x) mod 5 = 2x，在R7[X]/(X2+1)上分解得到(10 + 12x) mod 7 = 3 + 5x；
    对于在R35[X]/(X2+1)上的(8 + 20x)，在R5[X]/(X2+1)上分解得到(8 + 20x) mod 5 = 3，在R7[X]/(X2+1)上分解得到(8 + 20x) mod 7 = 1 + 6x；
    在R5[X]/(X2+1)上，乘法结果是6x；
    在R7[X]/(X2+1)上，乘法结果是3 + 23x + 30x2 mod 7 = 1 + 2x；
    对于原模数Q，子模数qi，定义Mi = Q / qi，Mi-1 mod qi为 将多项式从Rqi复原到RQ的系数。在这个样例中：
    在R5[X]/(X2+1)上，Mi = 35 / 5 = 7；7x mod 5 = 1，解得x = 3；所以从R5[X]/(X2+1)复原到R35[X]/(X2+1)的结果是6x × 3 × 7 mod 35= 126x mod 35 = 21x mod 35；
    在R7[X]/(X2+1)上，Mi = 35 / 7 = 5；5x mod 7 = 1，解得x = 3；所以从R7[X]/(X2+1)复原到R35[X]/(X2+1)的结果是(1 + 2x) × 3 × 5 mod 35 = 15 + 30x mod 35；
    两个复原结果相加15 + 30x + 21x mod 35 = 15 + 16x mod 35，得到了正确结果。

    从上面的例子中可以直观发现，如果最初给出的输入多项式就以在各个子模数环上的形式表示，那么各个子环上的计算彼此完全可以并行，直到最终需要得出在原环上的计算结果时再合并。这种方法非常有利于加速CKKS算法，因而在许多软硬件部署中被广泛应用。CKKS的RNS变体[5]提供了将输入密文定义在若干子环上进行同态计算的算法流程，下文为之重新介绍，红字标注用于特别强调上文未提及，或者不同的地方。

    CKKS-Bootstrapping

    接下来分析CKKS自举相关的信息。主要参考最早的CKKS全同态化改进[7]，但不包含RNS化；[8]提供了最新的RNS-CKKS自举，提供了在CPU上目前最好的精度，效率和安全性。[10]是最早给出RNS-CKKS自举方案的文献，但是没有什么分析的必要。

    Gentry提出了最早的自举大致框架。在提出这种方法前，消除密文下多次计算而产生的噪音的唯一方式是将经过计算的密文解密到明文，然后重新加密，这样可以将密文下多次计算过程积累和产生的噪音清除，将噪音回复到刚执行加密的初始状态。这样做的问题是需要向服务器侧暴露私钥，或者接收服务器侧返回的尚未计算完的密文，再将清除了噪音的新密文返回。Gentry提出了在加密状态下通过密钥循环的方式刷新噪音的方法。

    上面的图很好的体现了Gentry提出的Bootstrapping的过程[9]。结合图上所示，首先我们需要生成两组（或多组）FHE的密钥(pk1,sk1),(pk2,sk2)。

    一开始，我们把原文m，通过pk1加密得到一个低噪声（fresh）的密文ctm。随后我们基于ctm同态的计算函数ϕ，得到ctϕ(m)。因为ϕ的复杂度较高，图上标注出来的噪音已经达到了临界值，我们无法进行更深层次的同态运算了。

    随后，我们可以做的是把整个密文ctϕ(m)通过pk2加密进一个全新的fresh的FHE密文当中（绿色标注），得到ctctϕ(m)。这个时候我们发现，虽然原本的密文ctϕ(m)已经到达了噪音上线，但是双重加密的密文ctctϕ(m)的噪音值是非常低的。

    这样以来，我们接下来需要做的事情，就是同态的计算FHE的解密（Dec）函数，就可以把嵌套在ctctϕ(m)内部的ctϕ(m)还原为ϕ(m)，然后就可以得到一个全新的ctϕ(m)了。由于Dec需要用到原本的密钥sk1，所以我们需要额外的提供一份加密在pk2下的sk1来用于同态计算。当在ct2下的计算再次到达临界时，重复上面的操作，只不过这次是将密文从(pk2,sk2)调换回(pk1,sk1)。这样密文可以在两组密钥间来回调换，进而实现无限次数的同态计算，即全同态FHE。

    对于CKKS，实现自举的具体方法却略有不同。虽然根本原因仍然是噪音随着同态计算而增大，限制CKKS成为FHE的直接问题却并不是噪音的增长，而是模数随着“重缩放”不断减小。因此，CKKS自举的直接目标是恢复因多次“重缩放”而缩小的模数。

    在有了以上铺垫的前提下，接下来就可以分析第5节介绍的CKKS自举了。5.1节介绍了填充满槽的明文所对应的密文自举。具体而言，执行了以下5个步骤：

    ModRaise（模升）：假定有一个需要执行自举的密文ct，模数经多次模约简已经降低到较低值q，对应的明文m(X)定义在Rq[X]/(XN+1)，有配套的私钥sk，那么根据上文对于“解密”的定义，当然有m(X) = [<ct, sk>]q。将解密过程中模约q之前的结果<ct, sk>命名为t(X)， t(X) = <ct, sk> = q·I(X) + m (mod XN+1)，其中I(X)是一个小多项式，其系数有界（∥I∥∞<K）。t(X)也可以被看作[<ct, sk>]Q0，Q0>>q，也能保证无论sk是何值，Q0一定大于∥<ct, sk> ∥∞。所以，选定一个Q0，将密文视作RQ0[X]/(XN+1)上的新多项式即可，ModRaise步骤无需更多计算。

    CoeffToSlot（同态解码）：Coeff指代编码后整数多项式系数，Slot指代编码前明文的最多N/2个槽。我们要对多项式的系数进行一个取模操作，但我们使用同态的加法和乘法来拟合取模操作，而同态的加法和乘法是针对Slot中的数做的，因此，要将系数放进Slot中。相当于做一个同态的密文解码操作，可以使用乘DFT矩阵的方法来实现。但这里有一个问题，多项式的系数是N个，而明文Slot只有N/2个，因此这一步要得到两个密文，分别加密z0′ = ( t0 , . . . , tN/2−1 ) 和z1′ = ( tN/2 , . . . , tN−1 )。令z′是在ModRaise步骤取得ct对应的t的编码前明文，U0和U1分别是4.1节提到的矩阵U的左半和右半，那么根据4.1节的公式，z′，z0′和z1′间也有以下关系

    EvalExp（同态取模）：这一步的目标是在同态下将t模q，由于t(X) = <ct, sk> = q·I(X) + m，进而还原到m的密文。直接在同态域内实现 [t]q​ 难度很大。作者选择使用三角函数和复指数函数来逼近 [t]q 函数。
    定义：S(t):=(q·sin⁡(2πt/q))/(2π)，用 S(t)来逼近 [t]q。进一步，定义：E(t):=(q·exp⁡(2πit/q))/(2π)。为何选 E(t)？因为 exp⁡(2πit/q)在复平面上有周期性，与[t]q的周期特性类似。另外，使用复指数可以简化逼近过程，因为指数函数 exp⁡ 和 sin⁡ 有成熟的多项式近似方法（如切比雪夫多项式近似，下文再次提到时会有详细分析），且更易于在同态域中计算。具体的选取理由和数学分析在[7]的第3节有详细陈述。

    对于实际计算操作来说，输入密文槽中有 tj=q·Ij+mj，其中 ∥Ij∥较小、mj<q。

    将 E(tj) 代入：E(tj)=(q·exp⁡(2πi(q·Ij+mj)/q))/2π=(q·exp⁡(2πiIj+2πimj/q))/2π

    由于 Ij​ 很小，exp⁡(2πiIj) 接近 1（但依然要精确控制误差）。最终，我们希望输出的槽值接近：E(tj)≈(q·exp⁡(2πimj/q))/2π.

    CKKS相关硬件工作

    CKKS自身的算法框架大致如图。虚线左侧（用户侧）的计算相对简单，包括编解码，加解密，但也有相关工作为其设计了硬件加速[11]；服务器侧的运算则相对复杂。我们以服务器侧的工作[12][13]简单阐述一下相关硬件工作的共同特点，并总结大致思路。

    为顶层算法设计硬件加速的通用思路是将算法整体拆解成若干高级算法的组合，并为这些高级算法总结出通用的基本操作。例如[12]将所有高级算法，包括同态加，同态乘，密钥切换，重线性化，旋转等总结出三种基本操作，即同态乘（NTT域下），NTT，INTT。注意[12]的作者似乎考虑KeySwitch会经常与其他操作构成流水，或者需要并行，而为KeySwicth用以上三种基本元素单独设计了一个模块。

    [13]的拆解方法略显诡异，它将同态加也视为一项基本操作，并且不在同态乘和同态加内设置约简，而使用外置的通用Barret约简。可以预见，[13]一定比[12]更节省资源（原文中没有给出资源比较），但是考虑到执行CKKS任务而非单纯比较基本操作所需的时间时，[12]设计的单独KeySwitch一定会起到增大并行度，增长流水线的作用。

    总而言之，如果仅仅关注CKKS的硬件加速的话，有以下两个点应当注意：

    第一个要注意的点在于包括CKKS在内的FHE由于并不像PQC一样有固定的输入输出，它的加速器设计不能基于假设初始状态所有有效信息都存储在片内；此外FHE的中间数据非常大，不得不将这些数据off-chip存放，而on-chip到off-chip之间的数据传输一般来说远慢于片内。因此，on-chip与off-chip之间如何取得平衡是一个重要的trade-off。

    第二个点是基本操作的拆分。仅硬件实现基本操作，然后不同的高级算法分时复用这些基本操作进而实现顶层算法是一种常用手段，也有利于资源节省，但是为了提高效率而为某些特定的高级算法设计专用的硬件也是可以接受的。在不同的应用场景下，这一项trade-off的取向可预计也将大有不同。

    最后给出一个总结，目前来看，FHE自身似乎还不够作为博士的研究方向。它的故事不够大， 并且很难找到创新的想法而不仅仅是改进性能的想法。最近会写一点FHE结合Transformer等的文章，以及关于其融合其他方向的探讨。
